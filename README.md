# BaseAudit Oracle x402

Read-only Base Mainnet runtime bytecode and EIP-1967 storage observations, priced at **$0.02 USDC per successful request**. This is a limited static heuristic, not a security audit or a token safety rating.

## What the service actually checks

- Verifies the RPC reports chain ID 8453 and reads code/storage at one numbered block.
- Walks EVM instructions and skips PUSH1-PUSH32 operands. Bytes inside PUSH operands are not reported as SELFDESTRUCT or DELEGATECALL instructions.
- Reports matching PUSH4 constants as selector hints, not confirmed functions or token interfaces.
- Reads EIP-1967 implementation, admin, and beacon address slots.
- Marks implementation code as **not analyzed**. An implementation pointer does not identify Transparent versus UUPS behavior or establish upgrade permissions.
- Reports beacon addresses, with **beacon implementation resolution unsupported**. It does not call the beacon's `implementation()` function or claim that its logic is resolved.

Every report includes `analysis_type`, `analysis_scope`, `confidence`, `data_sources`, a block number, and limitations. `risk_score` is null and `risk_level` is `NOT_ASSESSED`; missing warning signs are not proof of safety. `is_proxy: null` means no supported proxy determination, not that the address cannot be a proxy.

Linear decoding does not prove reachability and can interpret embedded data or compiler metadata as instructions. Selector hints may miss optimized dispatchers or collide with unrelated constants. SELFDESTRUCT presence does not prove code can be deleted; [EIP-6780](https://eips.ethereum.org/EIPS/eip-6780) restricts its effects. The slot observations follow [EIP-1967](https://eips.ethereum.org/EIPS/eip-1967), but do not establish that a contract actually delegates through those slots. No implementation traversal, transaction simulation, source verification, or control-flow audit is performed.

## Endpoints

| Endpoint | Behavior |
|---|---|
| `GET /v1/audit?address=0x...` | Paid bytecode and EIP-1967 observations |
| `GET /v1/proxy?address=0x...` | Paid EIP-1967 address-slot summary |
| `GET /` | Capabilities and price |
| `GET /.well-known/x402` | Two canonical paid GET resources |
| `GET /health` | Process status only; does not probe RPC |
| `GET /self-test` | Configuration only; does not expose free paid analysis |
| `GET /openapi.json` | Canonical API description |

An address is required and must contain exactly 20 hexadecimal bytes. POST compatibility accepts `{"address":"0x..."}` and is protected but hidden from discovery. Paid HEAD requests return a payment challenge and do not execute analysis. Malformed upstream data or an RPC failure returns a sanitized 502, with no successful settlement.

## Payment gate

`PAYMENT-SIGNATURE` is parsed as an x402 v2 authorization. The configured trusted facilitator must verify it before analysis runs. The response is buffered until settlement succeeds; only then is `PAYMENT-RESPONSE` emitted. Header presence, `X-Payment`, `Authorization`, and client-supplied receipts never grant access. No synthetic payment receipt is generated by the endpoint.

Missing facilitator configuration fails closed. Pending or unknown settlement returns HTTP 503 without a new payment challenge or a success receipt. It is not evidence that no funds moved; follow the reconciliation instructions before issuing another payment. EIP-3009 does not cryptographically sign the requested URI/method/body. The local nonce guard is process-local, including on Vercel; replicas do not share a durable settlement journal or response cache.

Configuration:

- `PAYEE_ADDRESS`: defaults to `0xb5aFc89b57Fa8270bB7261348179D28099BEa2a0`.
- `X402_FACILITATOR_URL`: explicit trusted HTTPS facilitator supporting exact USDC on Base.
- `X402_FACILITATOR_BEARER_TOKEN`: optional provider bearer token; static tokens are not automatic CDP JWT authentication.
- `X402_PUBLIC_BASE_URL`: deployed HTTPS origin, recommended behind a proxy.
- `BASE_RPC_URL`: defaults to `https://mainnet.base.org`; provider availability is not guaranteed.

## Local verification

Use Python 3.12 and the committed pinned dependency files:

```sh
python -m pip install --require-hashes -r requirements.lock -r requirements-dev.txt
python -m pytest -q
```

Tests use local mocks for the facilitator and RPC; they do not send payments or rely on live Base data. Regression coverage includes **`test_fake_header_does_not_unlock_resource`**, with assertions that analysis, RPC, and verification never run for fake headers, plus malformed upstream data, PUSH operand false positives, proxy scope, and discovery.

A local test pass does not establish live facilitator credentials, a successful chain settlement, Vercel deployment health, or indexing by an external marketplace.
